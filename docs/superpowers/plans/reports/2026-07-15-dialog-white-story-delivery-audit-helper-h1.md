## Risks

1. **Count-unit reachability is not currently demonstrated.** `countUnit=DialogService::prepareWhiteStoryTemplateOrAbsent` has only same-class overload edges in Cloud, while the real Wubei caller remains on a different DHXY method. Even after the Cloud core body is replaced, the chain would be callable in isolation but not reachable from the current real caller unless another already-authorized Cloud caller exists or the caller migration is explicitly added to scope.
2. **Runtime owner/wiring remains open.** The local handler has no visible production construction path, so enum/codec/dispatch presence alone does not prove that a polled `DIALOG_WHITE_STORY_TEMPLATE` command can reach the injected mechanics on the exact window context.
3. **Supplied-image ownership leaks in the current handler body.** `LocalRemoteGameCommandHandler:1561-1578` decodes a new `BufferedImage`; the mechanics intentionally treats supplied images as borrowed and never flushes them, while the handler has no `finally` flush. Normal return, stop, or exception therefore leaves the handler-owned decoded image undisposed.
4. **The binary integrity chain is one-sided.** Request SHA is recomputed before mechanics, but the handler accepts any `ImageIO.read`-decodable format rather than enforcing the declared PNG signature. On the return path, `DialogWhiteStoryTemplateMacroResult` checks only non-empty bytes/non-blank hash and dimensions/rect; it does not decode the bytes or recompute `frameSha256`. Because outcome canonicalization excludes `framePngBytes`, byte corruption/substitution can evade the outcome digest and reach Cloud fingerprint reconstruction.
5. **Baseline capture-failure/absent behavior needs an explicit line-by-line decision.** In `696a12b0`, a null/unusable fresh detection with non-null `absentTargetKeyword` still builds the absent action, using zero coordinates when no rect exists (`DialogService:981-989,1021-1051`). The local mechanics maps fresh `CAPTURE_UNAVAILABLE` to its own terminal, and the port contract says non-business terminals become empty. Unless final Cloud policy deliberately preserves the baseline branch, this changes fallback/state behavior without a recorded business difference.
6. **Public input acceptance can narrow accidentally.** Baseline `verifyWhiteStoryTemplate` skips null specs and null/blank template paths in place. Both new command-side spec records reject blank template paths. The final Cloud core must preserve the baseline skip/order semantics before constructing the closed command; direct mapping would turn a baseline skip into an exception.
7. The amended mechanics JavaDoc still says only MATCHED carries payload and every non-matched terminal carries none, although `STORY_MISS/STORY_ABSENT` now carry rect+dimensions. This is stale contract documentation on a safety-sensitive boundary.
