## Risks

1. **Real-caller gap.** The declared `countUnit=DialogService::prepareWhiteStoryTemplateOrAbsent` is internally callable but not reachable from the live Wubei public caller. The current 19-file delivery therefore does not by itself establish the required real caller -> Cloud Service -> local macro -> terminal path.
2. **Supplied binary contract is not strict end to end.** DHXY handler `LocalRemoteGameCommandHandler:1551-1578` recomputes SHA, but accepts any `ImageIO.read`-decodable format, does not check the full 8-byte PNG signature, and does not prove decoded width/height equal the supplied rect span before constructing `DialogDetection`. The command/result constructors also accept any non-blank SHA text rather than canonical lowercase 64-hex.
3. **Handler-owned image is not released.** The handler-created `suppliedImage` at `:1561-1578` is passed as a borrowed supplied detection. The mechanics intentionally never flushes borrowed frames, while the handler has no enclosing `finally`. Normal return, stop and exception paths therefore retain the decoded image owner.
4. **MATCHED return bytes are not authenticated on Cloud.** `DialogWhiteStoryTemplateMacroResult:58-70` checks only presence, declared rect/dimensions and coordinate algebra. `DialogService:1098-1135` decodes with generic `ImageIO.read`, then saves/fingerprints without checking PNG signature, decoded dimensions, or recomputed SHA. Because `framePngBytes` is excluded from the outcome digest, corrupt or substituted bytes can pass canonical digest verification and reach fingerprint reconstruction.
5. **Failure-to-business mapping needs an explicit parent table.** Baseline null/unusable fresh detection plus a non-null absent keyword does produce a rect-less absent marker, so CAPTURE_UNAVAILABLE has a baseline analogue. The new code also maps `BINDING_UNAVAILABLE`, every `MECHANICS_FAILED`, supplied-frame integrity/decode failure, and transport `NOT_EXECUTED` to that same business absence. Those migration/transport failures did not exist as business observations in `696a12b0`; treating them as `STORY_ABSENT` can drive the same-probe mirror retry/failure path in `docs/业务逻辑.md:545-568` instead of preserving an infrastructure failure.
6. **Exact HWND runtime route is still unowned.** Even with correct enum/codec/dispatch code, no production handler owner currently proves that a polled command receives the mechanics bean and executes under the intended window context.
7. **Safety-sensitive documentation conflicts with implementation.** `DialogWhiteStoryTemplateMacroResult:8-9` says Cloud recomputes a washed-crop fingerprint, while `DialogService:1114-1135` intentionally fingerprints the RAW artifact to match baseline. The implementation choice matches the inspected baseline call, but the public result contract text is stale.
