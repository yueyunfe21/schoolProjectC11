# 天庭任务流程大MD

> 本文是当前已确认的天庭任务流程草案，只记录业务流程，不代表已开始实现。

## 1. 接任务

### 接任务 NPC

- 名称：`李靖`
- 地图：`天宫`
- 游戏坐标：`(144, 114)`
- 到李靖附近后，沿用现有任务的标准 NPC 接任务流程：`NPC Click Smart` 点击李靖，等待任务对话框。

### 李靖识别 profile

- 已查到既有定义：李靖复用 `BAILONGMA` 黄色文字 profile，不是单独 profile。
- 需要完整 OCR 命中 `李靖`；天宫亮背景下保留逐候选 OCR 兜底。
- 现有验证记录：李靖 OCR 曾返回 `李靖`，分数 `0.95054`。

### 接任务对话框

1. 点击NPC
2. 本地匹配天庭对话框目录中的 `accept` 图片。fallback点击第一条绿色。
3. 若后续需要取消任务，点击第二条链接。
   - 当前正常流程不考虑取消，只记录该分支。

### 今日完成次数校正

- 本地命中并点击 `accept` 后，复用该次本地已持有的第一帧和点击前复核帧；两帧均为完整
  `640×300` dialog ROI。
- 云端直接对**完整 dialog ROI** 做 OCR，不得按“红字固定在第几行”的假设再裁剪或洗色。
  对话文本可换行，但完整文案 `今日已完成天庭任务：N次` 是唯一接受格式。
- 只有两帧读出同一个完整整数、且该数不小于本地已完成数时，才以此数覆盖本地计数并更新 UI；
  任一帧未读出、两帧不一致或数值倒退都保持本地计数。次数校正不得延迟本地 accept 点击。

## 2. tracker 定位与任务链接

1. 接任务后，从左侧 `tracker` 任面板务的 `anchor`。
2. 匹配天庭任务 `title` 模板，确定该任务的完整内容框（task box）。
3. 在该 task box 内：
   - 先本地匹配 `暗雷.png`；命中则把当前小任务标记为 `暗雷怪`。
   - 再获取绿色链接所在内容，交由云端识别绿色链接，本地执行点击。
4. 点击绿色链接后等待移动；角色移动中只等待，停下后按当前小任务类型处理。

### 2.1 task box 尺寸（2026-07-30 实测，以此为准）

天庭任务的 task box = 从 `title` 匹配点起，**左移 5px、宽 214px、高 78px**。
代码常量：`TaskTrackerPanelService.TIANTING_TRACKER_BLOCK_HEIGHT = 78`。

**高 78 是量出来的，不是估的。** 67555 窗口一帧的行像素剖面（y 相对 task box 顶部）：

| 行 | y 范围 | 内容 |
|---|---|---|
| 1 | 1–14 | `天庭任务[常规玩法]`（黄标题） |
| 2 | 20–33 | 正文第一行 |
| 3 | 37–50 | 正文第二行（绿链所在行，下划线 y=53） |
| 4 | **54–67** | 正文第三行 —— **`(暗雷战斗)` 在这一行** |
| — | 68–79 | 空白间隔 |
| 5 | 80–93 | 下一个任务的黄标题 |

所以 78 恰好包住四行、停在下一个任务标题（80）之前。

**曾经的 65 是错的**：它在 y=65 切断，把第四行 14px 字高的底部两行削掉，`暗雷.png` 原图匹配只有 **0.4158**；改 78 后同一帧 **0.9984**，绿链不变。阈值 `TIANTING_DARK_THUNDER_THRESHOLD = 0.85`（命中 0.9984 / 被切 0.41，取中间偏高）。

改这个常量前必须重新做行剖面，不要凭感觉加减。

## 3. 三种进入战斗方式

当前天庭任务按进入战斗的方式区分为三类：

1. **暗雷怪**：task box 命中 `暗雷.png`。不通过对话框点击进入，而是通过野外遇怪进入战斗。
2. **普通对话框怪**：点击绿色链接、移动停下后，匹配并点击“看打”对话框进入战斗。
3. **封妖符 `Alt+A` 直战怪**：仅限封妖符小任务；进入 Alt+A` 模式后，点击 `妖王幻影` 进入战斗。

### 对话框匹配优先级

普通怪绝大多数使用“看打”对话框，因此优先级固定为：

1. `看打.png`：命中立即点击，进入战斗。
2. `多谢.png`：命中立即点击，再按“多谢分支”继续。
3. `封妖.png`：只在“多谢分支”点击后等待约 1 秒再匹配；命中后进入封妖符坐标分支。
4. `卓越.png`：命中立即点击，进入战斗。
5. `妖王.png`：命中立即点击，进入战斗；其与前四项之间的精确优先级待后续确认。

除接任务的 `accept` 外，当前天庭目录已准备的任务模板为：`看打.png`、`多谢.png`、`封妖.png`、`卓越.png`、`妖王.png`、`暗雷.png`。

### 未覆盖对话框的统一 fallback

- 本地先按已定义的天庭 dialog 模板和优先级处理；本地已经命中模板时，不走 fallback。
- 若当前 dialog 的所有本地模板均未匹配成功，则把该 dialog 发送给云端处理。
- 云端对此类未知／未覆盖 dialog 固定返回**第一行绿色链接**。
- 本地收到结果后，点击该第一行绿色链接。

## 4. 停下后的处理

### 4.1 暗雷怪

1. 当前小任务已由 `暗雷.png` 标记为暗雷怪。
2. 停下后先检查是否处于飞行状态；若在飞行，先取消飞行（读不出飞行状态时**不要**按取消键——对已经在地面的角色按下去会把它送上天）。
3. 不点击普通战斗对话框，靠**走位**主动触发野外遇怪进入战斗。

**2026-07-29 补充实测（走位方式以本节为准）。** 不识别角色名字，只认地图：停下后取当前地图名，在下表里查这张图的两个巡逻点，**每秒一次左右交替右键点击**，直到客户端判定进入战斗。表外地图不猜坐标（走到任务区外没有廉价退路），给有限次预算后结束本轮并说明原因。

**蟠桃园例外（2026-08-04 用户确认）**：角色停下后，不立刻左右交替；先对右点连续右键点击两次，再按 `左 → 右 → 左 → 右 ...` 的顺序开始每秒交替巡逻。其余地图仍从正常左右交替开始。

坐标同样是屏幕绝对值，基点与封妖符共用 `(1317, 187)`；窗口相对 = 屏幕 − base。

| 地图 | 左点（屏幕） | 右点（屏幕） | 左点（窗口相对） | 右点（窗口相对） |
|---|---|---|---|---|
| 蟠桃园 | `(1617, 568)` | `(1737, 608)` | `(300, 381)` | `(420, 421)` |
| 瑶池 | `(1646, 462)` | `(2014, 465)` | `(329, 275)` | `(697, 278)` |
| 御马监 | `(1617, 652)` | `(1871, 660)` | `(300, 465)` | `(554, 473)` |

### 4.2 普通对话框怪

1. 按上述优先级匹配对话框。
2. `看打.png`、`卓越.png` 或 `妖王.png` 命中并点击后，进入战斗。
3. 若先命中 `多谢.png`，进入“多谢分支”。

### 4.3 `Auto+A` 直战怪

1. 此路径**只允许用于封妖符小任务**；其他天庭小任务不得进入 `Alt+A`。
2. 任务流程先进入外层 Alt+A` 模式。
3. 再调用 `NPC Click Smart` 点击 `妖王幻影` 进入战斗。
4. 此时 **不得使用 `NPC Click Smart` 内部自带的 `Alt+A 分支**；它只负责目标点击，避免重复进入 Alt+A。
5. 若 `NPC Click Smart` 未匹配到 `妖王幻影`：取消当前 `Alt+A 模式，导航回李靖，重新接任务。

## 5. [BR-TIANTING-001] 多谢分支

1. 点击 `多谢.png`。
2. 点击成功后，本地登记“等待使用封妖符”的当前任务状态；该状态不得按固定墙钟时间过期。
3. 后续观察周期继续匹配 `封妖.png`，即使同步上传或输入队列使相邻采样超过原来的 `2.5s`：
   - 命中 `封妖.png`：点击，进入“封妖符坐标分支”。
   - 未命中 `封妖.png`：回到左侧 tracker，再点击绿色链接；移动停下后匹配 `卓越.png`，命中即点击进入战斗。
4. “等待使用封妖符”只在 `封妖.png` 实际点击成功、天庭 Dialog interest 明确清除或当前任务运行态重置时清除；
   采样间隔和 Cloud 往返耗时不能替代这些业务事实。

## 6. 封妖符坐标分支

### 进入条件

- 首次进入分支的权威事实是：已在前置 Dialog 中成功点击 `使用封妖符`，即消费到
  `ACTION_FENGYAO`。点击成功后，左侧 `tracker` 才会更新为封妖符任务，因此不得反过来要求
  `tracker` 先出现“封妖符”才允许进入分支。
- 更新后的 `tracker` 标题仍是 `天庭任务`，内容包含 `封妖符`；该事实用于确认分支仍有效以及暂停、恢复后的
  状态恢复，不替代首次 `ACTION_FENGYAO`。
- 目标 NPC／怪物：`妖王幻影`

`ACTION_FENGYAO` 建立分支后，封妖符专属流程必须压住通用绿色链接流程。只有坐标对话框 anchor
`fengyaofu.png` 未命中时，才允许点击当前 Tracker 绿色链接一次以重新打开坐标对话框；anchor 已命中时禁止点击
Tracker。

### 坐标顺序

每次封妖符小任务内按顺序处理。只有 Runner 证明该坐标点击确实启动移动后，才把它记为已处理；点击后未移动
不消费该坐标，必须先检查是否有 `story dialogue` 挡住，命中则用既有 `Fast Click` 清除，然后重试同一坐标。

### 单个坐标流程

1. 鼠标左键点击当前尚未点击的坐标，并为该次点击登记 exact pathing intent。
2. 只有 Runner 对该 exact intent 给出真实移动事实，才把坐标记为已处理并等待自动巡路；角色移动中只等待。
   - 若点击已发送但 Runner 未证明移动，只检查是否有 `story dialogue` 挡住；命中后用既有 `Fast Click` 清除。
   - 无论本次是否发现 STORY，都不得跳到下一坐标；清掉该次无移动 intent 后重试同一坐标。
3. 确认停下后，进入外层 `Auto+A` 模式。
4. 在点击 `Alt+A` 前记录完整 `tracker` 内容。
5. 调用 `NPC Click Smart` 点击 `妖王幻影`，并禁用其内部的 `Auto+A` 分支。该次点击只允许使用可见
   tooltip 候选，不读取或写入 NPC 点击记忆，也不走黄字、人物锚点公式或 Ctrl 菜单。

### 封妖符后的分支

#### 触发进入战斗

1. 等待战斗结束。
2. 若脱战后存在 `story dialogue`，先用既有 `Fast Click` 点掉，再比较完整 task box。
3. task box 内容已经变化，说明本小任务结束；退出封妖符分支并进入下一小任务。
4. task box 内容未变化时，先检查坐标对话框 anchor：anchor 已存在则直接选择下一个尚未点击坐标；anchor
   不存在才点击左侧绿色链接一次，确认 anchor 后再选下一坐标。不得无条件重点击 Tracker。

#### 未触发进入战斗

1. 确认当前窗口为 `story dialogue`，再使用既有 `Fast Click`；只有物理点击实际提交才算该未入战结果已处理。
   - 当前约定：目标点击未进战时必定出现该 story dialogue；尚未检测到或点击未提交时继续等待当前坐标，不能提前比较。
2. 比较 `Alt+A` 点击前后的完整 tracker 内容：
   - 内容变化：本小任务直接完成；退出封妖符分支并进入下一小任务。
   - 内容未变化：先检查坐标对话框 anchor；已存在则直接点击下一坐标，不存在才点击 Tracker 绿色链接一次重开，
     随后处理下一个尚未点击坐标。
3. 在 Runner 未确认 `IN_COMBAT` 且 `story dialogue` 尚未被实际处理前，只能继续等待当前坐标结果；物理点击
   `dispatched=true` 不能作为入战、未入战或任务完成证明，也不能提前比较 task box。

### task box 内容变化判据（2026-08-04 用户确认）

- 取 parser 已确定的完整 task box ROI，保持原分辨率与原 RGB，直接比较两帧图片；不洗背景、不洗色、
  不缩放，也不用 OCR 关键词代替图片比较。
- 使用 normalized RGB correlation：`score >= 0.80` 为同一内容，`score < 0.80` 才确认内容变化。
- 任一帧不可读、格式错误或尺寸不一致都属于 `INDETERMINATE`，不得当作内容变化。
- 封妖符已有待处理坐标时，该坐标的到达与直战动作优先于 task box 比较；不得在
  `STOPPED_AWAY -> Alt+A -> 妖王幻影` 之前用画面差异提前退出封妖符分支。

若四个坐标均已处理但 tracker 内容未变化：**导航回李靖并与他对话重新接任务**（2026-07-29 用户决议，Q4）。走过去而不点他等于白走一趟；也不要因此切回“接任务”阶段——任务还挂在 tracker 上时那个阶段会短路直接弹回小任务循环，形成来回弹跳。

## 7. [BR-TIANTING-002] 战斗结束后的通用处理

### 战斗与子任务 watchdog 的硬边界（2026-08-01 用户确认）

- 点击绿色链接后建立的“任务框未变化”watchdog **只适用于非战斗阶段**。
- 一旦 Runner 确认进入战斗，必须立刻清零该 watchdog；战斗时长不得计入其预算，也不得在战斗中因为超时进入回城／重接任务。
- 确认脱战后，不恢复旧计时；只能由新的 tracker 面板事实或新的绿色链接操作重新建立 watchdog。
- 因此，`IN_COMBAT` 的唯一任务主循环动作是 `PARK_COMBAT` 与自动战斗维护；不得导航、使用回城道具或进入接任务流程。

每场战斗结束后，由队长按以下固定顺序观测和处理：

1. 使用现有自动战斗／正常战斗结束处理后，**先检查左侧是否仍存在天庭任务 `title`**：
   - `title` 已消失：当前一轮任务已经完成，直接按既有回城道具流程回城。
   - 回城道具使用失败：不再继续当前战后链路，导航回李靖并重新接任务。
   - `title` 仍存在：继续以下当前小任务的战后处理。
2. 放权给与修罗、五倍一致的队员恢复逻辑：
   - 允许队员补血、补蓝。
   - 检测到队员死亡离队时，队长打开队员 `TEAM_RETURN` / `COMMON_BOX` 能力并**释放 task turn**；不得在队长线程内同步等满固定时间。
   - 归队信号仍在时，队长只做短周期 park + 复查，禁止点击下一条绿色链接或导航；信号消失后关闭该能力才恢复原流程。
   - 归队信号的读取失败或结果未决不是“无人待归队”，必须 fail-closed，不能放队长继续。
3. 保存战斗前的 tracker 截图或等价内容快照。
4. 本地匹配 `引妖.png`：
   - 脱战确认后固定等待 `1` 秒，再开始一次本地匹配。
   - **未命中：立即结束引妖步骤，继续 title / 绿色链接；不得等待或重试。**
   - 命中则本地鼠标左键点击，再比较 tracker 内容是否变化。
   - 只有“已实际点击且 tracker 未变化”才再次本地匹配；再次命中才继续点击，累计实际点击不超过 5 次。
5. 战后恢复先比较当前 fresh 天庭 Tracker 内容与本场暗雷进战前保存的内容指纹：
   - 本场由暗雷左右巡逻进入战斗，且两份完整 task box 的原图相关分数 `>= 0.80`：证明当前暗雷小任务没有完成。不得点击绿色
     链接，不得重新检查飞行器，也不得重新初始化巡逻点；直接复用进战前的左右点和巡逻游标，从下一侧
     继续移动遇怪。
   - 内容指纹已经变化，或本场并非由暗雷巡逻进战：继续走当前小任务的普通恢复入口，点击左侧 Tracker
     绿色链接进入后续导航。
   - 尚未得到 fresh Tracker：继续等待，不得拿旧画面推断“内容相同”，也不得提前点击绿色链接。
6. 暂停、停止、新 run、重新接任务或 Tracker 内容变化时，必须清除暗雷连续性证据；迟到事实不得恢复
   上一场或上一小任务的巡逻。

## 8. 一轮任务完成与回城

- 天庭任务以 6 次小任务为一轮。
- 左侧天庭任务 `title` 消失，表示这一轮 6 次任务已经完成。
- 只有此时才按既有回城道具流程回城，再重新前往李靖接任务。
- 回城道具成功、确认已回到天宫后，才进入与修罗一致的队员归队门：有归队信号则让权等待，归队完成才结束本轮。
- 回城道具使用失败时，直接导航回李靖重新接任务。
- 不能因为单次战斗结束就使用回城道具。
- 整个天庭任务中，只要在尝试识别左侧title的时候，如果没有看见，就应该先去任务栏找回城道具使用，如果使用道具没有回城，或者没有道具，都应该手动导航重新去接任务。
