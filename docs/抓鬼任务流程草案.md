# 抓鬼任务流程草案

## 2026-07-31 初始独立基线

`抓鬼` 是一个独立任务，运行标识为 `CATCH_GHOST` / `catch_ghost`，展示名称为“抓鬼”。

- 初始实现完整复制当前“江湖历练”的 Client、Cloud、协议、观察兴趣、本地 dialog、配置和资源路径；复制完成后两套任务必须可以独立演进。
- 首个版本暂时沿用江湖历练已有的业务时序、模板内容、导航、战斗、回城与维护策略。这里的“沿用”仅指初始行为，不允许抓鬼后续改动回写江湖历练。
- 抓鬼拥有独立的云端包 `com.bot.dhxy.task.zhuagui`、客户端任务枚举和 `catchGhostMaxRuns` 配置；模板复制到 `images/template/zhuagui`、`images/template/dialog/zhuagui` 与 `bag/zhuagui_return_item.png`。
- 用户尚未定义抓鬼的 NPC、地图、坐标、标题图、对话框和入战图时，不擅自替换初始复制的资源内容；后续由用户逐项提供并只改抓鬼的独立路径。

## 首次运行验收

1. 主控任务列表单独显示“抓鬼”，江湖历练及其他任务保持不变。
2. 启动抓鬼时 Client 与 Cloud 使用 `CATCH_GHOST` / `catch_ghost`，Cloud 工厂创建独立 `CatchGhostTask` 实例。
3. 抓鬼的任务次数单独保存；修改抓鬼次数不得改变江湖历练次数。
4. 初始模板文件与江湖历练内容一致但路径独立；后续替换抓鬼模板不得影响江湖历练。

## 2026-07-31 抓鬼暗雷分支（用户实机确认）

- 当前窗口实测：抓鬼标题 `zhuagui_title.png` 得分 `0.975541`、窗口坐标 `(24,311)`；按天庭规格得到
  任务内容框 `(19,311,214x78)`。天庭 `anlei.png` 在该内容框得分 `0.988879`（阈值 `0.85`），命中窗口
  坐标 `(37,350)`，因此抓鬼确实包含暗雷小任务。
- 抓鬼使用天庭 `images/template/tianting/anlei.png` 的独立字节副本
  `images/template/zhuagui/anlei.png`；不得使用此前 A3 来源的同名文件。
- 每次点 Tracker 绿链后用该腿的同一任务框只分析一次暗雷标记；仍先按正常绿链移动。到达或停下后，暗雷
  分支不等本地看打：先安全读取飞行状态，仅确认飞行才按 `Alt+C` 下飞行，随后调用既有
  `WildBattleTask.nextFourPoint(...)` / `clickBundle(...)` 四点右键巡逻遇怪。
- **巡逻中途的选项对话框 = 验证，点第一条链接**（2026-07-31 用户实机确认）。巡逻打到暗雷时游戏会弹一个
  选项框，这是它故意给的一次验证；**只认左键**，而巡逻发的是 `clickBundle` 右键（走位），右键永远选不中
  它，不处理就会一直右键点过去、任务停在那里。所以巡逻每一拍在发下一枪之前先用
  `detectDialogTypeNoFocus(..., waitBeforeCaptureMs=0)` 看一眼当前屏：是 `OPTION` 就用天庭同一条
  `DialogHandleRequest.fallbackFirstOption(...)` 点第一条绿选项，点中（`FALLBACK_CLICKED`）后这一拍不再
  巡逻，直接 park 等 Runner 的战斗边沿。到达但一枪未发时没有可验证的东西，不探测；读不出/没点成都不算
  失败，下一拍再看。合同：`CatchGhostDarkThunderPatrolDialogContractTest`（7 条）。
- 入战后沿用自动战斗；战后继续使用新鲜抓鬼 title 判定：title 仍在则继续绿链，title 消失则导航回地府钟馗。
  绿链每次重点都会把暗雷整块状态清零重判（`withShortcutTrackerClick`），所以战后"该是什么就是什么"：
  还是暗雷就重新巡逻，不是就走普通绿链。

## 2026-07-31 本地看打起始延迟

- 抓鬼与江湖历练均在 Tracker 绿链真实点击后等待 `10 秒`，才开始绑定窗口的本地看打模板 probe。
- 旧的 `25 秒`复制值会使角色已经停止、尚未弹出 dialog 时长期没有任何看打检查；只调整这两个独立任务，修罗保持原值不动。

## 2026-07-31 抓鬼正式循环

1. 接任务 NPC 固定为 `地府` 的 `钟馗 (29,55)`。
2. 抓鬼不使用回城道具，也不在移动中打开包裹预扫描。战后 title 消失时，直接正常导航回地府钟馗。
3. 抓鬼不做修装备。巫医维护仍保留，统一使用洛阳城原修装备位置 `(324,109)` 的抓鬼巫医；三技能维护
   沿用全局用户开关。
4. 本地接任务先匹配 `accept.png`。点击后必须读取抓鬼 title：title 出现才算接取成功；title 未出现时，
   再点钟馗、匹配并点击 `cancel.png` 清空该 dialog，最后第三次点钟馗重新接任务。不得保留江湖历练的
   `accept_normal.png`、`quzhuagui.png` 或模板 miss 后点 Tracker 绿链的旧接任务分支。
5. 每场预期战斗脱战后，先建立“不得早于本次 `COMBAT_EXITED`”的新 Tracker 帧边界，清除战前绿链事实；
   title 仍存在则继续第一条绿链，title 消失则导航回地府。不得用战前或战斗重绘前的旧 Tracker 帧点击。

### 当前实现记录

- `accept.png` 与 `cancel.png` 都只在 Client 本地模板匹配并原子点击；Cloud 仅通过 typed
  `CATCH_GHOST_*_DIALOG_TEMPLATE` 取得枚举结果，不下发坐标。
- `accept -> title` gate 失败时才进入一次 cancel 链，接任务模板 miss 不会转成 Tracker/绿链点击。
- 抓鬼流程不再调用回城道具、回城道具预扫或修装备维护。保留三技能维护的全局用户开关；巫医维护目标为
  洛阳 `(324,109)`。
- 新模板已同步到 Client `images/template/dialog/zhuagui/` 与 Cloud
  `src/main/resources/images/template/dialog/zhuagui/`；完整原始帧 + 红框 replay 待实例停止后补齐。
