# 江湖历练任务流程草案

## 2026-07-30 初始独立基线

`江湖历练` 是一个独立任务，运行标识为 `XINSHOU_TRAINING` / `xinshou_training`，展示名称为“江湖历练”。

- 它不是既有 `XINSHOU` / “新手”任务的改名、分支或替代；既有新手任务及其标题、30 秒锁和业务流程保持不变。
- 初始实现完整复制云端 `XiuluoTaskV2` 及其配套状态对象，形成独立包 `com.bot.dhxy.task.xinshoulilian`。
- 在业务规则尚未另行定义前，江湖历练暂时沿用修罗的目标、模板、导航、战斗、回城和维护流程；后续需求只能改动江湖历练的独立代码，不回写修罗。
- 客户端任务选择、回合调度、观察兴趣、预检和协议校验以独立的 `XINSHOU_TRAINING` 任务码运行。

## 已确认的阿三对话框与唯一入战入口

- 接任务对话框只允许客户端绑定窗口本地模板匹配，不再调用修罗的 Cloud dialog fallback。
- 匹配顺序固定为：
  1. `images/template/dialog/a3/accept_normal.png`：点击后按正常接任务成功继续。
  2. `images/template/dialog/a3/accept.png`：点击只表示重置当前对话框；随后回到

  3. `images/template/dialog/a3/quzhuagui.png`：只识别、不点击；表示江湖历练当前不可继续，
     立即正常结束整个江湖历练任务，不再开始下一轮。
- 删除江湖历练复制来的修罗接任务旧分支：修罗本地接受模板、Cloud 绿字 fallback、人数不足
  确认/等待、取消任务可见性判断均不得参与阿三接任务。
- 江湖历练进入战斗只有一个模板点击入口：`CONFIRM_ENTER_BATTLE` 阶段在客户端绑定窗口本地
  匹配 `images/template/dialog/a3/kaida.png`，命中后原子点击并等待 Runner 确认进入战斗。
- 删除江湖历练复制来的其他入战入口：修罗 `kanda` 后台 watcher、prepared action 点击、
  通用修罗 dialog 列表、目标点击失败时的模板/OCR/野怪取消/`Alt+A` 直接战斗恢复，以及
  `NpcClickRequest.expectedDialogTemplatePath` 的修罗看打验证。真正的修罗任务保持不变。
- tracker 快捷导航终态不再注册修罗看打兴趣；到达或停下后统一转入上述唯一
  `CONFIRM_ENTER_BATTLE` 阶段。

## 通用主包裹任务页启动校准

- 主包裹任务页不是江湖历练专属状态。所有任务的任务页道具操作都不得假定固定为第六页。
- 每次任务启动批次完成角色预检、尚未发出任何远程任务循环前，只由 Cloud 已确认身份的队长窗口开包并匹配
 任务页签图；按页签中心相对 `anchor_cunkuan.png` 的纵向步长反推零基页码，并将该页码保存在进程内。
- 此后所有任务、所有窗口只复用该固定页码，再以**各自窗口**的 `anchor_cunkuan.png` 坐标加原有页签公式
  计算点击点；不重复匹配页签，不按窗口分别猜页，也不回退盲点第六页。
- 队长未完成启动校准前，任何窗口不得自行点击任何猜测的任务页；本轮任务页道具操作只记录未校准并返回。
- 缓存仅在程序进程终止时自然失效；暂停、战斗、关闭包裹、任务轮次推进或任务短暂停止均不清除。

### 队长 tooltip 预检不得以 UNKNOWN 放行

- 本地 hover 到队伍 tooltip 后，只有抓到可供 Cloud OCR 的有效 mask 才算预检完成；本地不猜测
  `LEADER` 或 `MEMBER`。
- 首次悬停未得到有效 tooltip 时，必须先把鼠标移出 hover 命中区，再短等并重新悬停、重新截图；在启动后的
  `30 秒` 预检窗口内持续重试，得到有效 mask 即继续。
- `30 秒` 内仍无结果，或用户暂停/停止取消时，该批启动必须整体拒绝；不得把截图失败、模板未出现或 tooltip
  空白写成 `UNKNOWN` 后继续启动。Cloud 继续负责用代表 mask OCR 队长 ID，并和每个窗口标题比较。
